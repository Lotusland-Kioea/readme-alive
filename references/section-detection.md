# 段落检测与风格继承规范

> **权威来源**：本文档是段落检测、关键词匹配和风格继承的唯一权威定义。SKILL.md 中的规则为摘要，如有不一致以本文档为准。

## 设计理念

**不留痕迹**：利用用户 README 自身的标题结构作为自然边界。不插入任何标记。工具退出后 README 中无残留。

## 段落识别

### 关键词匹配算法

在 `--fix` 模式下，解析 README 的 H1-H3 标题。匹配前执行以下预处理：

1. **Emoji 剥离**：移除标题前缀中的 emoji 字符。覆盖以下 Unicode 范围：
   - `U+1F300`–`U+1F5FF`（杂项符号和象形文字）
   - `U+1F600`–`U+1F64F`（表情符号）
   - `U+1F680`–`U+1F6FF`（交通和地图符号）
   - `U+2600`–`U+26FF`（杂项符号）
   - `U+2700`–`U+27BF`（装饰符号）
   - 同时移除变体选择器 `U+FE0F`、零宽连接符 `U+200D` 以及 `U+FE0E`（文本变体选择器）
   
   示例：`## 🚀 快速开始` → `快速开始`；`## 🛠️ Tech Stack` → `Tech Stack`

2. **大小写不敏感匹配**：所有关键词匹配不区分大小写。`Tech Stack`、`tech stack`、`TECH STACK` 等效。

3. **子串匹配**：关键词作为子串出现在标题中即视为匹配。`## 项目技术栈一览` 中 `技术栈` 子串匹配成功。

4. **宽泛关键词限制**：以下关键词具有高度泛用性，匹配时附加额外条件：

   | 宽泛关键词 | 所属段落类型 | 限制条件 |
   |-----------|-------------|---------|
   | `Quick` | quick-start | 仅当标题同时包含 `Start` / `开始`，或整词匹配 `Quick Start` 时生效 |
   | `Structure` | project-structure | 仅当标题同时包含 `Project` / `项目` / `Directory` / `目录` / `Code` / `源码` / `Architecture` / `Organization` / `Layout` 时生效 |
   | `命令` | interface-overview | 仅当标题同时包含 `CLI` / `子` / `行` / `Command` / `接口` / `API`，或整词匹配 `命令行` 时生效 |
   | `设置` | config-reference | 仅当标题同时包含 `配置` / `Configuration` / `Config` / `环境` / `变量` / `Env` / `Settings` / `Options` / `Parameters` 时生效 |

   不满足限制条件时，该关键词不产生匹配，但不影响同标题中其他关键词的匹配。

### 关键词到段落类型的映射

```
## tech-stack（技术栈）
含"技术栈|技术选型|依赖|依赖项|Dependencies|Tech Stack|Built With|Stack"
    → tech-stack

## project-structure（项目结构）
含"项目结构|目录树|目录|文件结构|源码结构|Project Structure|Architecture|Organization|Layout|Code Structure|Structure"(需满足限制条件)
    → project-structure

## interface-overview（接口概览）
含"API|接口|端点|路由|CLI|子命令|命令"(需满足限制条件)|Endpoint|Command|Router|Routes|Controllers|Services|Handlers|接口文档|API文档|CLI 命令"
    → interface-overview

## quick-start（快速开始）
含"快速开始|安装|启动|运行|入门|使用|开发指南|构建|部署|Getting Started|Quick"(需满足限制条件)|Installation|Setup|Development|Building|Usage"
    → quick-start

## config-reference（配置参考）
含"配置|环境变量|设置"(需满足限制条件)|Configuration|Config|Env|Settings|Options|Flags|Parameters|.env|变量"
    → config-reference
```

- 中英文关键词同时检查
- 竖线 `|` 分隔的关键词为"或"关系，命中任意一个即匹配

### 匹配度计算规则

一个段落类型可能匹配到多个标题（如同一文档中同时存在 `## 安装` 和 `## 快速开始`，两者均匹配 quick-start）。此时按以下优先级选择**唯一**目标标题：

1. **精确完整词匹配 > 部分子串匹配**
   - 精确匹配：关键词作为独立词语出现（英文：由空格/标点分隔的完整单词；中文：由空格/标点/英文单词边界分隔的连续汉字序列）
   - 部分匹配：关键词作为更长词语的子串出现
   - 示例：标题 `Quick Start` 对关键词 `Quick Start` 为精确匹配；标题 `QuickStart Guide` 对关键词 `Quick` 为部分匹配

2. **同精度时按命中关键词数量降序**
   - 统计标题中命中的关键词总数（中英文合并计数）
   - 示例：`## 快速开始 Installation` 命中 `快速开始` + `Installation` = 2 个关键词，优先于仅命中 `快速开始` 的标题

3. **关键词数量相同时按标题层级（H2 > H3 > H1）**
   - H2 优先于 H3，H3 优先于 H1
   - 理由：H2 通常是 README 的顶级章节标题，H1 是项目名

4. **同层级按出现顺序取第一个**
   - 在 Markdown 源文件中先出现的标题优先

### 段落边界

从匹配标题的下一行起，到下一个同级或更高级标题前止。**H4 及更深层级的子标题（H5、H6）也视为段落边界**——不会吞掉子标题及其所属内容。

### H4 段落边界特殊处理

**quick-start 段落内的 H4 流程步骤不切割**。当 quick-start 段落内部存在 H4 子标题作为流程步骤标记时（例如 `#### 1. 安装依赖`、`#### 2. 配置环境`、`#### 3. 启动服务`），整段统一处理，不按 H4 边界分割。

识别规则：连续 H4 标题包含序号模式（`1.`/`2.`/`步骤一`/`Step 1` 等）且位于 quick-start 段落内时，将这些 H4 视为段落内部结构而非独立边界。

### 非中英文 README 降级策略

对于日语、韩语、法语等非中英文 README，标题匹配按以下顺序降级：

1. **英文关键词匹配**（优先）：使用英文关键词集合尝试匹配
2. **自定义关键词匹配**：检查项目根目录是否存在 `.readme-alive-keywords.json`（格式见下方"自定义关键词"章节），使用自定义关键词进行匹配
3. **追加模式**：以上均无匹配时，不在段落级别修改现有内容，改为在 README 末尾追加建议章节（以注释形式标注 `<!-- suggested by readme-alive -->`，用户可自行决定保留或删除）

## 风格继承

`--fix` 生成替换内容前，必须先嗅探并继承用户现有风格。

### 标题风格

| 元素 | 继承策略 |
|------|----------|
| Emoji 前缀 | 精确复用（如 `## 🛠️ 技术栈`） |
| 语言 | 中文 README → 中文列头；英文 → 英文列头 |
| 层级 | 精确复用 `#` 数量 |

### 表格风格

| 元素 | 继承策略 |
|------|----------|
| 列数 | **严格保留原列数** |
| 列头 | 保留不修改 |
| 对齐 | 精确复用 `:---` 等 |
| 空行 | 精确复用 |

### 代码块风格

| 元素 | 继承策略 |
|------|----------|
| 语言标签 | 精确复用（bash/python/java 等） |
| 缩进 | 精确复用 |
| 注释风格 | 继承原代码块风格 |

### 目录树风格

| 元素 | 继承策略 |
|------|----------|
| 树形前缀 | `├──`/`└──`/`│` 精确复用 |
| 注释标记 | 保留重要注释（如 `← 入口`），移除过时标记 |
| 缩进宽度 | 精确复用 |

### 链接风格

| 元素 | 继承策略 |
|------|----------|
| 链接格式 | 检测现有 README 中链接的风格比例。reference-style 链接（`[text][id]` + `[id]: url`）占比 > 50% → 使用 reference-style；否则使用 inline 链接（`[text](url)`）。新生成的链接采用相同风格。 |

### 列表前缀

| 元素 | 继承策略 |
|------|----------|
| 无序列表前缀 | 检测现有 README 的无序列表前缀（`-` 或 `*`）。`-` 占比 > 50% → 使用 `-`；否则使用 `*`。混合使用时按多数决定。 |
| 有序列表格式 | 精确复用 `1.` / `1)` 等格式 |

### Badge 行格式

| 元素 | 继承策略 |
|------|----------|
| Badge 样式 | 检测现有 Badge 的 URL 模式（shields.io / flat / flat-square / for-the-badge 等）。新增 Badge 使用相同样式。 |
| Badge 分隔符 | 检测 Badge 之间的分隔方式（空格 / 换行），精确复用。 |

### 水平分割线风格

| 元素 | 继承策略 |
|------|----------|
| 分割线字符 | 检测现有 README 中水平分割线的字符（`---` / `***` / `___`）。精确复用最先出现的类型。无现有分割线时不添加。 |

## 降级策略

### 零基场景（段落内无对应结构）

| 场景 | 降级行为 |
|------|----------|
| 段落内无现有表格 | 使用项目类型对应模板的默认风格（见末尾"模板默认列数速查表"） |
| 无现有代码块 | 使用 `bash` 作为默认语言标签 |
| 无现有 emoji | 不使用 emoji |
| README 语言不确定 | 根据项目注释语言推断 |

### 中间态场景（有结构但不规范）

| 场景 | 降级行为 |
|------|----------|
| 表格存在但列头与新数据列数不对齐 | **按原列头重建**：保留原列头文本，新数据按原列数合并或截断。行末追加 `<!-- 列数已调整 -->` 注释标记。stderr 输出警告："列数与模板默认值不一致（原 N 列，模板 M 列），已保留原列头。" |
| 代码块存在但语言标签与实际内容不符 | **保留标签 + 标注**：保留用户原始语言标签，在代码块首行添加注释 `# [non-standard]` 标注非标准标签。不静默修改用户标签。 |
| 表格存在但对齐格式缺失或不一致 | 按该表格第一行的对齐方式统一所有列的对齐格式 |

### CI/非交互模式

当 `--non-interactive` 标志激活时（典型场景：CI/CD 流水线、自动化脚本）：

| 行为 | 说明 |
|------|------|
| 列数变化处理 | **默认保留原列数**，不提示用户选择 |
| 警告输出 | 所有警告写入 stderr，格式：`[readme-alive][WARN] <message>` |
| 确认提示 | 全部跳过，默认执行。等效于对所有确认提示回答 `y` |
| 交互式逐个确认 | 不可用，自动降级为全部确认 |
| 环境检测 | 自动检测 `CI` 环境变量（常见 CI 系统均设置此变量）；同时检测 `--non-interactive` 标志 |

`--non-interactive` 标志不影响审计和修复的质量，仅改变用户交互行为。审计报告 `metadata` 中标注 `"interactive": false`。

### 非中英文 README 追加模式

见上方"非中英文 README 降级策略"章节。

## 自定义关键词

### 文件格式

支持项目根目录放置 `.readme-alive-keywords.json` 文件，为非中英文项目或在标准关键词无法覆盖的场景下自定义标题关键词映射：

```json
{
  "tech-stack": ["技術スタック", "Technologies", "기술 스택"],
  "project-structure": ["構成", "ディレクトリ構成"],
  "interface-overview": ["API一覧", "コマンド"],
  "quick-start": ["はじめに", "セットアップ", "시작하기"],
  "config-reference": ["設定", "環境変数", "환경 설정"]
}
```

- 每个 key 对应一种段落类型（`tech-stack` / `project-structure` / `interface-overview` / `quick-start` / `config-reference`）
- 每个 value 是该类型对应的自定义关键词数组
- 所有 key 均为可选，只需配置需要覆盖的类型
- 自定义关键词与宽泛关键词限制规则同样适用于自定义关键词（如自定义的 `Quick` 等同受限制条件约束）

### 合并策略

自定义关键词与内置中英文关键词**合并**（非替换）。匹配时同时检查内置关键词和自定义关键词。内置关键词优先级高于自定义关键词（先检查内置、命中即停止）。

### 零开销行为

`.readme-alive-keywords.json` 文件不存在时不做任何操作，无文件 I/O、无警告、无性能影响。

## 非 Git 环境下段落检测行为

段落检测不依赖 Git——仅解析 README 的 Markdown 结构即可完成。但以下行为会受影响：

| 功能 | Git 可用 | Git 不可用 |
|------|---------|-----------|
| 段落检测 | 正常 | 正常（无影响） |
| 风格继承 | 正常 | 正常（无影响） |
| `--fix` 段落更新 | 正常 | 正常（无影响） |
| 增量审计（检测变更文件） | 使用 `git diff` | 降级为全量扫描 |
| 审计报告元数据 | 正常 | 标注 `[No Git]` |

无 Git 时，建议用户初始化 Git 仓库以获得增量审计的优化体验。

## 模板默认列数速查表

以下列出每种项目类型 × 段落类型的默认列数和列头名称（中文）。英文 README 时列头替换为对应英文。

### Web 应用（web-app）

| 段落类型 | 默认格式 | 列数 | 默认列头 |
|---------|---------|------|---------|
| tech-stack | 表格 | 3 | `技术` `版本` `说明` |
| quick-start | 代码块 | - | - |
| project-structure | 目录树 | - | - |
| interface-overview | 表格 | 3 | `方法` `路径` `说明` |
| config-reference | 表格 | 3 | `配置项` `默认值` `说明` |

### CLI 工具（cli-tool）

| 段落类型 | 默认格式 | 列数 | 默认列头 |
|---------|---------|------|---------|
| tech-stack | 文本段落 | - | - |
| quick-start | 代码块 | - | - |
| project-structure | 目录树 | - | - |
| interface-overview | 表格 | 2 | `命令` `说明` |
| config-reference | 表格 | 3 | `选项` `默认值` `说明` |

### 库/SDK（library）

| 段落类型 | 默认格式 | 列数 | 默认列头 |
|---------|---------|------|---------|
| tech-stack | 文本段落 | - | - |
| quick-start | 代码块 | - | - |
| project-structure | 目录树（建议） | - | - |
| interface-overview | 表格 | 2 | `函数/类` `说明` |
| config-reference | 表格 | 4 | `选项` `类型` `默认值` `说明` |

### Monorepo（monorepo）

| 段落类型 | 默认格式 | 列数 | 默认列头 |
|---------|---------|------|---------|
| tech-stack | 文本段落 | - | - |
| quick-start | 代码块 | - | - |
| project-structure | 目录树 | - | - |
| interface-overview | -（Monorepo 通常不设独立接口章节） | - | - |
| config-reference | 列表（非表格） | - | - |

## 与旧版锚点系统的对比

| 维度 | 旧（锚点） | 新（段落检测） |
|------|----------|--------------|
| 用户 README 中的痕迹 | `<!-- readme-alive:auto:xxx -->` | **无** |
| 初始化 | `--init` 插入标记 | 无需初始化 |
| 修改范围 | 围栏式（标记对之间） | 自然段落（标题之间） |
| 卸载后 | 锚点残留需手动清理 | **无残留** |
