# README 质量标准

基于 CNCF、Google、GitHub、OpenSSF、Standard Readme、keepachangelog、awesome-readme 等 9 个权威来源的共识提炼。

## 核心职责

README 是项目的着陆页，必须回答：**这是什么？怎么装？怎么用？**

## 标准章节

| 章节 | 必要性 | 说明 |
|------|--------|------|
| 项目名称 + 一句话描述 | 必须 | 做什么、解决什么问题 |
| 徽章行 | 建议 | CI 状态、许可证、版本号 |
| 安装/快速开始 | 必须 | 可复制的命令 |
| 使用示例 | 必须 | 代码片段展示核心用法 |
| 技术栈 | 建议 | 主要依赖和版本 |
| 项目结构 | 建议 | 目录树 + 简要说明 |
| API 概览 | 按需 | 有 API 的项目 |
| 配置说明 | 按需 | 关键环境变量/配置项 |
| 贡献指南 | 必须 | 或链接到 CONTRIBUTING.md |
| 许可证 | 必须 | SPDX 标识符 + 链接 |

## 不该在 README 中的内容

| 内容 | 应该放哪里 |
|------|-----------|
| 版本变更日志 | CHANGELOG.md |
| 开发过程记录 | Git commit history |
| 学习笔记/知识体系 | docs/ 或 Wiki |
| 数据库建表 SQL | docs/schema.sql 或迁移脚本 |
| 架构决策记录 | docs/adr/ |
| 操作时间戳/同步记录 | .readme-alive-log.json |

## 比例化长度标准

不定死数字，按项目规模比例判断。

| 复杂度 | 项目特征 | README 合理范围 |
|--------|----------|----------------|
| 1-2（微型） | <20 源文件，单模块，单语言 | 50-150 行 |
| 3-4（小型） | 20-100 源文件，少量模块 | 100-250 行 |
| 5-6（中型） | 100-500 源文件，多模块 | 200-400 行 |
| 7-8（大型） | 500-2000 源文件，多模块/多语言 | 300-600 行 |
| 9-10（巨型） | 2000+ 源文件，Monorepo | 400-800+ 行 |

**规则**：
- 低于合理范围下限 → 🟡 Warning：可能缺少关键信息
- 高于合理范围上限 → 🔵 Info：考虑内容迁移到 docs/ 或 CHANGELOG
- 在合理范围内 → 不报长度相关告警

## 审计哲学

- 不强制用户必须有某些章节
- 只审计准确性：用户已有的内容是否与代码一致
- 缺少关键章节作为 Info 级别建议
- 长度建议基于比例，不搞一刀切
